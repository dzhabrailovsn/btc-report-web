# Промпт автоматизации для веб-версии (скопировать целиком в scheduled task)

Двойной ежедневный прогон AI-отчёта BTC: 03:20 (ночной — сразу после закрытия дневной UTC-свечи в 00:00 UTC) и 08:20 (утренний полный; если запуск попал в другое окно — делай полный вариант). Определи режим по текущему часу МСК: ~3 = ночной, ~8 = утренний.

Все команды выполнять из каталога пакета (где лежит update_report.py). Все файлы (ai_take.json, events.json, btc_report.html и т.д.) — в этом же каталоге.

=== НОЧНОЙ РЕЖИМ (~03:20) ===
1. python update_report.py (до 10 мин). Итог в report_run.log: OK/PARTIAL допустим (Binance может отдавать 451 — движок сам уходит на OKX-фолбэки); FAIL/STALE — один повтор.
2. ИИ-ВЕРДИКТ ПО СВЕЖЕМУ ЗАКРЫТИЮ D1: прочитать btc_full.json (особенно daily_status: причинные tested_res_prior/trap_res_prior/w1_defense), liq_map.json, events.json. 1 веб-поиск только если были крупные ночные новости ("bitcoin market news today"). Записать ai_take.json строго формой: {"generated":"YYYY-MM-DD (сегодня UTC)","verdict":"решение одним предложением","confidence":0-100,"reasons":["3-5 причин с числами из JSON; фокус — что показало только что закрывшееся D1: закреп/оборона/ловушка"],"allocation":[["условие","действие","% капитала"],"минимум 4 строки: текущая ситуация / сценарий А (вход/стоп/цели, размер = 100×риск1%/дистанция стопа, минимум 2R) / сценарий В / суммарный лимит риска ≤2%"],"geo":[["факт/новость с источником","влияние на BTC-план"],"0-3 строки только при свежих (≤12ч) новостях, иначе []"],"invalidation":"цены/события смены мнения"}. Уровни брать только из JSON, не выдумывать. Пересобрать: python btc_report_html.py.
3. Ответ коротко: ГЛАВНОЕ — изменился ли вердикт движка после нового D1-закрытия, цена, твой вердикт с уверенностью. Приложи ссылку на btc_report.html.

=== УТРЕННИЙ РЕЖИМ (~08:20) ===
1. КАЛЕНДАРЬ: 1–2 веб-поиска событий на 4–6 недель ("CPI release date next month BLS", "FOMC meeting schedule", "bitcoin events calendar"). Подтверждённые даты записать во временный файл events_new.json формате [{"date":"YYYY-MM-DD","title":"...","impact":"high|med|low|holiday","time":"опц.","source":"auto"}], затем: python events_update.py events_new.json (сам дедуплицирует; записи с пометкой «ориентир, подтвердить» при появлении подтверждённой даты можно удалить). Поиск недоступен — пропустить шаг.
2. python update_report.py (до 10 мин; OK/PARTIAL допустимы; FAIL/STALE — один повтор).
3. ИИ-ВЕРДИКТ С ГЕО: 1–2 веб-поиска свежих (≤3 дней) гео-новостей ("geopolitics markets news this week Fed oil tariffs", "crypto market news today geopolitics"). Прочитать btc_full.json, liq_map.json, backtest.json, events.json. Записать ai_take.json той же формой, что ночной (reasons: минимум одна причина — от гео-новостей; честно помечай устаревшие/недоступные данные, например ETF). Пересобрать: python btc_report_html.py.
4. Ответ коротко: статус, цена BTC, вердикт движка, новые события календаря, твой вердикт + ключевая гео-новость + рекомендация по капиталу, уверенность. Приложи ссылку на btc_report.html.

=== ОБЩЕЕ ===
- Файл btc_report.html — единственный результат: проверить свежесть (<10 мин от сейчас, >100 КБ). Ничего не копировать на рабочий стол (в облаке его нет), серверы не поднимать, скрипты не переписывать (только если полностью сломаны — тогда зафиксируй ошибку из report_run.log и примени минимальный фикс).
- При двух неудачных запусках пайплайна — зафиксируй ошибку и пропусти шаг ИИ-вердикта.
- Если в среде нет какого-то файла пакета — сообщи, какой отсутствует, и остановись.
